# Studio vision (not built yet — Coming soon)

**Status:** Nav + placeholder only. Do not implement product until capture → evidence → MCP fidelity is solid.

## What Studio is

Governed AI design studio for iGaming. Library captures + favourites/trending patterns + industry research feed an agent that prototypes under the **customer’s own tokens / brand guidelines / design system** — never competitor trademarks.

## Example pattern intelligence

From approved evidence + usage signals, Studio can recommend:

- Rainbet-style side nav (most used pattern in segment)
- bet365-style betslip
- Stake-style activity feed + casino lobby
- Whale.io-style my account
- FanDuel-style onboarding

## User loop

1. Connect / link **their** site (owned URL) + upload **their** tokens / components / governance.  
2. Chat with the agent: e.g. “what would our site look like with Stake.com navigation?”, “add popular sports patterns into our sportsbook”, “rebuild our sports front end like Paddy Power”.  
3. Get mocks → refine → prototype.  
4. Agent uses Blaast MCP skills + cited evidence; layout follows customer system; references are interaction/IA only.

## Constraints (non-negotiable)

- Customer tokens win over reference styling.  
- No copying logos, assets, or proprietary source.  
- Every suggestion cites evidence IDs.  
- Different product UX than Design Studio internals — Studio is the customer-facing agent surface.

## When to build

After: capture coverage → approve → publish index → MCP `get_evidence` / `get_motion` returning measured structure/motion reliably.
